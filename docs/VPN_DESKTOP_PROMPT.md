# Задача: Flutter-клиент Oksana VPN для macOS

Работай с существующим Vue-проектом и отдельным Flutter desktop-проектом:

- `../oksana-vpn-ui` — действующий Web и Telegram Mini App. Используй его как визуальный референс и источник существующих API-контрактов. Не ломай его и не копируй его компоненты.
- текущий проект `oksana-vpn-desktop` — Flutter desktop-приложение. Не используй Tauri.

На первом этапе реализуй только две страницы:

1. Ввод UUID подписки и загрузка пользовательских Xray-профилей через существующий API.
2. Управление подключением: включение/отключение, выбор профиля/сервера и выбор доступного режима.

Другие страницы пока не добавляй.

## Архитектура и платформы

- Используй Flutter и Dart для интерфейса приложения.
- Первая рабочая платформа — macOS ARM64 (Apple M1).
- Сразу отдели UI, загрузку подписки и управление VPN за небольшими типизированными границами.
- Заложи общий контракт VPN runtime, чтобы позже добавить macOS, Windows и Linux реализации без изменения экранов и моделей.
- Сейчас реализуй только macOS. Не создавай фиктивные Windows/Linux адаптеры или заглушки.
- Не создавай дополнительные проекты `flutter/` и `desktop/` рядом друг с другом: текущий `oksana-vpn-desktop` является Flutter-проектом. Не создавай отдельный Rust-проект, `shared/`, workspace или монорепозиторий без конкретной необходимости.
- Текущую Vue-версию оставь без изменений. Возможный перенос Web и Telegram Mini App на Flutter — отдельное решение и отдельный этап.

## Ввод UUID и API

Используй текущий публичный backend-контракт:

`GET https://connect.oksana1984.ru/start?token=<UUID>`

Публичный `/start` проксируется на backend `/connect-v2`. Он принимает UUID пользователя в параметре `token` и возвращает JSON-массив Xray-профилей, а не обычный VLESS URI или Base64.

- Сделай URL endpoint настраиваемым при сборке; не добавляй секреты или API credentials в приложение.
- Валидируй UUID до запроса, показывай loading, пустой результат и понятные ошибки API.
- Показывай список серверов/профилей по их `remarks` или безопасному отображаемому имени.
- UUID является credential для доступа к подписке: не выводи его в логи, аналитику или ошибки и не сохраняй в незашифрованном виде.
- Сохраняй UUID в системном защищённом хранилище (macOS Keychain через `flutter_secure_storage`); профили серверов оставляй только в памяти приложения.
- Не изменяй backend и его формат ответа без необходимости.

## VPN-экран

Покажи:

- состояние: `disconnected`, `starting`, `running`, `stopping`, `error`;
- выбранный сервер/профиль;
- режим подключения `Proxy` или `TUN`;
- кнопку подключения/отключения;
- понятные ошибки без приватной конфигурации.

Профиль можно менять только когда runtime остановлен. Подключение не должно называться активным VPN, пока нужная сетевая функция действительно готова.

## Proxy и TUN

### Proxy

- Используй Xray-core и профиль, полученный от backend.
- Для первого этапа запускай Xray с локальными SOCKS/HTTP inbounds из профиля (обычно `127.0.0.1:10808` и `127.0.0.1:10809`). Проверяй, что процесс запущен и соответствующий локальный порт принимает соединение.
- Явно называй это состоянием «локальный прокси запущен». Не утверждай, что весь системный трафик macOS проходит через него.
- Не меняй системный proxy автоматически. Если будет добавлено применение системного proxy macOS, сначала запрашивай подтверждение и сохраняй настройки для надёжного восстановления.
- Не запускай произвольные shell-команды и не передавай исполняемые пути через IPC. Установка привилегированной службы допускается только через отдельный сопровождаемый installer, вызванный стандартным macOS authorization dialog при первой настройке.

### TUN

- Текущая целевая реализация только для macOS ARM64: отдельный root LaunchDaemon запускает bundled Xray с нативным macOS `utun` inbound. Не возвращай Packet Tunnel System Extension без отдельного решения пользователя.
- Первая установка выполняется из приложения одним стандартным macOS administrator authorization dialog. После этого приложение управляет службой через узкий UID-проверяемый Unix socket с командами только `start`, `stop`, `status`.
- Устанавливай helper, Xray, geodata и LaunchDaemon plist в root-owned защищённые пути. Не принимай произвольные пути, shell-команды или Xray binary от UI.
- Для Xray TUN используй `autoSystemRoutingTable` и `autoOutboundsInterface: auto`, чтобы соединения самого Xray не попали в туннель. macOS DNS из поля `dns` автоматически не меняется; сохраняй исходные DNS-серверы системных сетевых служб и восстанавливай их при остановке/перезапуске службы.
- Не показывай TUN connected только по состоянию кнопки или живому процессу: проверяй запуск Xray и появление нового `utun`. End-to-end маршруты, DNS leaks, сон/пробуждение и аварийное восстановление всё равно требуют реальной проверки на Mac.

## Работа с Xray

- Не подменяй подключение фиктивным состоянием.
- Ограничь API runtime командами подключения, отключения и чтения статуса.
- Не допускай нескольких процессов Xray от одного приложения.
- Читай stdout/stderr процесса без записи конфигураций и UUID в логи.
- Удаляй временный приватный конфиг после остановки и при штатном завершении.
- Если Xray binary или его geodata отсутствуют, оставь соответствующую функцию выключенной и покажи понятное объяснение.

## Порядок работы

1. Изучи UI-референс, текущие инструкции и контракт API.
2. Создай Flutter-приложение в текущем проекте и воспроизведи визуальную систему UI.
3. Реализуй ввод UUID и загрузку профилей через `/start?token=...`.
4. Реализуй экран выбора сервера и состояния управления VPN.
5. Подключи реальный локальный proxy runtime на macOS, когда доступен Xray binary.
6. Реализуй TUN через macOS LaunchDaemon и Xray `utun`; опиши реальные требования к маршрутам/DNS и не имитируй его работу.
7. Оставь Windows/Linux для отдельной реализации через тот же runtime контракт.

Используй существующие инструменты. Если Flutter SDK, Xray binary или реальный backend-доступ недоступны, продолжай независимые части и укажи точный блокер.
